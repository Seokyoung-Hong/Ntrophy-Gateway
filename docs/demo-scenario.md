# NovemberAiGateway 데모 시나리오 (PoC, 약 6분) — 구현 반영판

핵심 한 줄: **게이트웨이가 아는 호출보다 공급자가 보고하는 사용량이 많으면 키가 유출된 것이다.** 감지하면 그 키를 즉시 폐기하고 예비키로 전환한다.

## 0. 구성 요소
| 구분 | 설명 |
|---|---|
| 대표 (Admin) | 대시보드 조작자. 크레덴셜 등록, 사용자 토큰 발급, 허용 IP(선택, 기본 모두 허용)·**허용 무단 호출 수(한도)** 설정 |
| 사용자 A, B | 게이트웨이(OpenAI 호환 API)로 호출. 공급자 키를 받지 않음 |
| 청중 / 공격자 | 유출된 키로 **공급자에 직접** 호출(게이트웨이 우회) |
| Gateway | 중계 + 접근통제 + 사용량 기록 + 탐지·자동 대응 + 사용량 집계·예측 |
| 공급자 | **Mock Provider**(리허설·정밀 시연) / **OpenRouter 라이브 모드**(실제 GPT, 청중 참여) / OpenAI 어댑터(실제 호출 수 API) |

## 1. 탐지 원리 (발표 핵심)
- 공급자 보고는 항상 게이트웨이 기록보다 **늦다**. 그래서 `공급자 값 > 게이트웨이 기록`이면 오탐 없이 유출이다.
- 공급자가 **호출 수**를 주면 그대로 비교(OpenAI: 분 단위 버킷), **비용만** 주면 비용 차이로 비교하고 호출 수는 평균 호출 비용으로 추정(OpenRouter).
- 판정은 한도(허용 무단 호출 수, 기본 100)의 10% SUSPECT / 50% WARNING / **70% 자동 차단**. 한도는 대표가 바꾼다.
- 차단선을 70%로 둔 이유: 집계 지연·폴링 동안 늘어나는 호출을 흡수해 최종 손실이 한도 아래에 머물게 하기 위함.

## 2. 장면별 진행

### 장면 1. 등록 (1분)
1. 대표가 크레덴셜 등록: **K1(주 키, API Key)**, **S1(예비 키)**, **K2(WIF: 장기 키 없이 15분 단기 토큰)**. 화면에는 마스킹(`sk-...a9f2`)만, 원문은 암호화 저장.
2. (선택 설정) **허용 IP 대역(사내 + VPN CIDR)** 등록. 등록하지 않으면 모두 허용(기본). 사용자 A·B에게 게이트웨이 토큰 발급(원문은 1회만 노출).
3. **한도 설정**: "허용 무단 호출 수 = 100".
- 프론트: 크레덴셜 카드(방식·상태·마스킹), 한도 입력, CIDR 목록(내부/VPN), 사용자 토큰 목록.

### 장면 2. 정상 운영 (40초)
1. 사용자 A·B가 호출 → 200. 허용 대역을 하나 등록한 뒤 그 밖 IP로 호출하면 403 + 거부 로그(출발 IP 표시). 시연 후 대역을 지우면 다시 모두 허용.
2. 대시보드: 게이트웨이 기록과 공급자 보고가 겹침, 차액 ≈ 0, 상태 NORMAL.
3. **사용량 화면**: 사용자별 호출·토큰·누적 비용, 단가표 기반 예상 비용, 월말 예측과 예산 도달 시점(선형 추정).

### 장면 3. 유출 (30초)
- 내레이션: 대표가 K1을 게이트웨이 밖에 복사해 쓰다 공개 저장소에 올림. 시스템은 아직 모른다(= 탐지 지연 문제).

### 장면 4. 무단 사용 (30~60초)
- **라이브 청중 모드(권장)**: 슬라이드의 QR/주소로 접속한 청중이 "유출된 키"로 실제 GPT를 씀(`/live`, OpenRouter 라이브 모드). 호출은 게이트웨이를 거치지 않는다.
- **백업**: 대시보드 버튼으로 공격 시뮬레이터 시작(Mock, 초당 5회).
- 대시보드: 공급자 선만 치솟고 게이트웨이 선은 평평 → 차액 게이지 상승. SUSPECT(노랑) → WARNING(경고 토스트). Mock 공격(초당 5건) 실측: 약 6초 SUSPECT, 약 14초 WARNING, 약 18초 BLOCKED, 약 21초 RECOVERED.

### 장면 5. 자동 차단 — 하이라이트 (30초)
1. 차액이 한도의 70%(실제 공급자 모드는 35%)에 도달 → BREACH.
2. 자동 대응(타임라인에 단계별 표시): ⓪ 탐지(DETECTED) ① 공급자에서 K1 폐기 ② 예비키 S1을 주 키로 승격 ③ 관리자 통보 ④ 승격 키로 호출 확인. ②~④의 1초 간격은 연출용 표시(실제 승격은 폐기 직후).
3. 상태 **BLOCKED**(빨강). 청중 화면에는 "이 키는 폐기되었습니다 (401)".
   - Mock: 즉시. OpenRouter: 비활성화 반영까지 최대 약 20초.
4. 요약 카드: 차단까지 걸린 시간, **손실 호출 수 < 한도**, 폐기된 키, 전환된 키.

### 장면 6. 복구 (20초)
- 사용자 호출은 같은 토큰으로 **끊김 없이 200**(내부적으로 S1 사용). 상태 RECOVERED(10초 유지) → NORMAL.

### 장면 7. 허니키 (선택, 10초)
- 게이트웨이에 심어 둔 가짜 토큰(공개 저장소·위키에 노출된 것처럼)으로 접근하면, 호출자에게는 평범한 401이 가지만 내부에서는 사고가 생기고 전체 API 토큰이 즉시 폐기되고 모든 서비스가 일시 정지된다. 시연 버튼 `POST /demo/honeypot/hit`(출발 IP 203.0.113.77 가정).

### 장면 8. 한계와 확장 (30초, 슬라이드)
| 공급자 | 호출 수 반영 지연 | 키 폐기 반영 |
|---|---|---|
| Mock | 2초 | 즉시 |
| OpenRouter | 사용액 약 6초(호출 수 API는 당일 미지원) | 비활성화 후 최대 약 20초 |
| OpenAI | **95~381초**(실측 2회, 정확한 호출 수. 반영 전에도 "공급자 > 게이트웨이" 확실 유출 경로가 먼저 SUSPECT를 낸다) | 서비스 계정 삭제 후 약 3초 |
| vLLM(자체 GPU, 비용 0원, **해커톤 데모 전용 — 실제 아키텍처 그림에는 넣지 않음**) | 0~2초(앞단 게이트웨이 계량) | 즉시. 공격 시뮬레이터 사용 가능(`POST /demo/reset-vllm`) |
- 공급자 지연만큼 탐지가 늦어지고, 그 사이 손실은 호출 속도 × 지연이다. 자동 대응은 **사후 피해를 줄이는 도구**이며 완전 예방이 아니다.
- WIF·Vault로 장기 키 노출을 줄여도 게이트웨이 자체 침해는 막지 못한다 → 허니키로 게이트웨이 공격을 탐지.
